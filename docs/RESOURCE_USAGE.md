# 리소스·갱신 정책

v2.16.15 · 2026-11-09

| 작업 | 주기·조건 |
| --- | --- |
| 메뉴바 시세 표시 | 패널 닫힘 1초, 열림 0.5초. WebSocket 수신은 유지하고 최신 값만 모아 UI에 전달합니다. |
| 시장 매크로 | 시장 탭에서 약 9~10분. |
| ETH/BTC·Funding | 시장 탭에서 약 1분. |
| OI | 자동 조회 시 수신 후 5분 동안 재사용. 수동 갱신은 대기를 우회합니다. 고유 수신 시각이 10분 이상 지나면 해석에서 제외합니다. |
| ETF·스테이블 공급·중기 추세 | 시장 탭에서 약 30분. ETF 보고서 날짜는 수신 시각과 별도로 검증합니다. |
| 국내 거래소 | 보이는 탭에서는 약 1분. 백그라운드에서는 비교 표본을 준비하는 동안 3분, 정상 수신 거래소의 15분 비교가 가능하면 15분입니다. |
| 실패 거래소 재시도 | 거래소별 최소 3→5→15분. 실제 시도는 위 수집 주기에 맞춰 이뤄집니다. 수동 갱신은 대기를 우회하며 실패 상태를 정상으로 바꾸거나 예전 값을 새 표본에 섞지 않습니다. |
| 24시간 비교값·미니 차트 | 수신 후 10분 재사용. 화면 복귀나 차트 설정 변경으로 캐시 수명을 연장하지 않습니다. |
| 화면 꺼짐·잠자기 | 시세 연결, 고양이 동작, 주기 조회를 중단하고 복귀 시 재개합니다. |

미니 차트는 켜진 항목에 필요한 입력만 받습니다. Binance만 켜면 Binance 캔들 한 종류, Upbit만 켜면 Upbit BTC 캔들 한 종류를 받습니다. 김치프리미엄은 Binance BTC·Upbit BTC·Upbit USDT 세 입력이 모두 필요하며, 이미 유효한 입력은 재사용합니다. 짧은 시간에 설정을 연속 변경하면 250ms 동안 모은 뒤 요청합니다.

캐시는 메모리에만 보관합니다. 만료된 값으로 조회 실패를 숨기지 않으며, 취소된 요청은 캐시에 기록하지 않습니다. 시계가 뒤로 이동하면 캐시를 다시 확인합니다. 긴 백그라운드 대기에는 작은 실행 시각 여유를 허용하므로 표의 주기는 정확한 초 단위 보장이 아닙니다.

시장 해석은 화면 갱신당 한 번 계산해 요약·근거·확인 순서와 지표 카드에서 함께 사용합니다. 개별 OI 수신 시각은 상세 카드에 표시하며, 다른 값의 갱신으로 바꾸지 않습니다.

## 검증 범위

제어된 시계와 가짜 HTTP 응답으로 요청 수, 실패·취소·복구와 만료 처리를 검사합니다. BTC → BTC+Upbit → 전체 차트를 순서대로 켜는 검사에서는 필요한 HTTP 요청이 총 세 번입니다. 이 결과는 중복 요청 감소를 확인한 것으로, CPU·메모리·배터리의 일정 비율 절감을 보장하지 않습니다.
