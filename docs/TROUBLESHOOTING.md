# 문제 해결

먼저 앱 버전·태그, macOS·칩, ZIP/Git 설치 여부와 막힌 단계를 확인합니다. 표준 설치·업데이트·복구는 [BUILDING.md](BUILDING.md)에 있습니다.

아래 보조 명령은 최신 `main` 기준입니다. **v2.16.5 릴리스 ZIP·태그에서는 `scripts/`를 빼고 실행합니다.** 예를 들어 `bash scripts/compatibility_check.sh` 대신 `bash compatibility_check.sh`를 사용합니다. `setup.sh`는 두 소스 모두 최상위 폴더에 있습니다.

## Swift를 찾지 못하거나 `xcrun: error`가 표시됨

```bash
xcode-select --install
```

설치 후 새 터미널에서 확인합니다.

```bash
xcrun swift --version
bash scripts/compatibility_check.sh
```

전체 Xcode나 Homebrew를 무조건 추가 설치할 필요는 없습니다. 출력된 실제 도구 경로와 오류를 확인합니다.

## `Permission denied: ./setup.sh`

압축을 푼 소스 폴더에서 실행합니다.

```bash
chmod +x *.sh
bash setup.sh
```

## 실행했는데 Dock에 없음

Catoshi는 메뉴바 앱입니다. 화면 위쪽 메뉴바를 확인하세요. 직접 실행하려면:

```bash
open ~/Applications/Catoshi.app
```

메뉴바가 꽉 차 있거나 노치가 있는 Mac에서는 Finder·Spotlight에서 실행 중인 Catoshi 앱을 다시 열면 패널이 표시됩니다. 메뉴바 아이콘 자체를 찾으려면 다른 메뉴바 항목을 줄여 확인합니다. 여전히 보이지 않으면 `bash scripts/diagnose.sh` 결과로 프로세스와 설치 상태를 점검합니다.

## 빌드·서명·아이콘 생성이 실패함

```bash
bash scripts/compatibility_check.sh
bash scripts/diagnose.sh
```

에러가 발생한 첫 단계와 마지막 메시지를 함께 확인합니다. 새 앱은 사전 검증 후 교체하므로 빌드 실패를 해결하려고 기존 설치 앱이나 설정을 지우지 않습니다.

`iconutil: Invalid Iconset`은 실제 아이콘 파일 문제 또는 제한된 실행 환경에서 생길 수 있습니다. 일반 Terminal에서 같은 릴리스 소스의 `bash scripts/build_app.sh`를 실행해 재현되는지 확인합니다. 실제 파일 문제가 확인되기 전에는 아이콘 파일을 임의 삭제하거나 시스템 보안 설정을 바꾸지 않습니다. 재현 여부와 오류 전문을 Issue에 적어 주세요.

## 업데이트 실패 또는 새 버전이 실행되지 않음

- 빌드·사전 검증 단계에서 실패했다면 기존 앱을 다시 실행하고 오류를 제보합니다.
- 새 버전으로 교체된 뒤 문제가 생겼다면 v2.16.5 이상 소스 폴더에서 복구합니다.

```bash
bash scripts/rollback_app.sh
```

복구 스크립트는 보관된 이전 앱을 검증하고 현재 앱과 교환합니다. 백업이 없다는 안내가 나오면 마지막 정상 버전의 릴리스 소스 ZIP을 받아 별도 폴더에서 `bash setup.sh`를 실행합니다. 자세한 절차는 [복구 가이드](BUILDING.md#이전-앱으로-복구)를 참고하세요.

업데이트·복구는 저장된 설정과 Activity Radar 기록을 지우지 않습니다. 버전만 복구해도 해결되지 않는 문제는 데이터를 삭제하기 전에 진단 결과를 확인합니다.

설치 도중 중단되거나 교체가 실패하면 스크립트가 기존 앱 복구를 시도합니다. 자동 복구 자체도 실패한 경우 오류 메시지가 수동 복구용 경로를 안내합니다. 이때 안내된 `.catoshi-stage.*` 폴더에는 기존 앱이나 백업이 남아 있을 수 있으므로 삭제·덮어쓰지 말고 보존하세요. 표시된 경로와 오류를 개인정보가 없는 범위에서 Issue에 남겨 복구 절차를 확인합니다.

## Rosetta 관련 오류

Apple Silicon Mac에서는 터미널을 native 상태로 실행해야 `arm64` 빌드를 만들 수 있습니다.

```bash
uname -m
```

Apple Silicon native 터미널은 `arm64`, Intel Mac은 `x86_64`를 표시합니다. Apple Silicon에서 `x86_64`가 나오면 Terminal의 Rosetta 실행 설정을 확인한 뒤 일반 Terminal에서 다시 시도합니다.

## 시장 데이터가 갱신되지 않거나 오래된 상태임

인터넷 연결과 해당 지표의 마지막 갱신·수신 상태를 확인합니다. 외부 API 점검·응답 제한·데이터 발표 주기 때문에 지표마다 시점이 다를 수 있습니다. ETF 일별 흐름 같은 데이터와 실시간 시세가 같은 주기로 갱신되는 것은 아닙니다.

네트워크 복귀 뒤 갱신되는지 기다립니다. 기존 숫자가 남아 있다는 사실만으로 최신 값이라고 판단하지 마세요. 수신 실패나 오래된 상태의 값을 이용한 자동 해석은 제한될 수 있습니다. 특정 API 변경으로 계속 실패하면 앱 업데이트가 필요할 수 있습니다.

제보할 때 지표 이름, 화면에 보이는 상태·시각, 네트워크 복귀 여부를 적습니다. 시장 수치가 포함된 스크린샷을 외부에 올리기 전에 제공자 조건을 확인하고, 가능하면 상태 문구와 오류만 텍스트로 전달해 주세요.

## 국내 거래소 Activity가 `측정 중`

Activity Radar는 로컬 표본을 모아 기준선을 만듭니다. 실행 후 화면이 켜진 동안 표본을 모으며 빠른 추정이 먼저 나오고 이후 15분 활동 값으로 전환됩니다. 표본 부족·거래소 점검·수신 실패가 있으면 비교가 제한될 수 있습니다. 정상적인 측정을 기다리기 위해 기록을 초기화할 필요는 없습니다.

## 공유 카드의 숫자가 비어 있거나 추정·불완전 상태임

공유 카드는 BTC·김프, 시장 맥락, 국내 거래소 수치를 담으며 Feed / Story / Square, 이미지·캡션 복사, PNG 저장, 시스템 공유를 제공합니다. 필요한 데이터가 아직 수신되지 않았거나 계산 기준이 부족하면 값을 만들지 않고 대기·불완전·추정 상태를 표시합니다.

카드의 생성 시각과 데이터의 기준 시각을 구분해 확인하세요. 오래된 값이나 거래소 일부만 수신된 결과를 전체 시장의 최신 값으로 해석하지 않습니다. 앱의 해당 화면에서도 수신 상태를 확인하고, 계속 불일치하면 앱 버전·카드 유형·상태 문구를 제보해 주세요.

카드를 외부에 공유할 때는 포함된 데이터의 제공자별 조건과 필요한 출처 표시를 확인합니다. 확인된 조건과 아직 불확실한 범위는 [데이터 출처](DATA_SOURCES.md)에 기록합니다. 개인 사용 소프트웨어 라이선스나 무료 직접 빌드가 제3자 데이터의 재공유 권한을 대신하지는 않습니다.

## 제보와 지원 범위

[GitHub Issue](https://github.com/Rayeonjin/Catoshi/issues)에 다음을 적어 주세요.

- Catoshi 버전·태그, macOS·칩
- ZIP 또는 Git, 첫 설치 또는 업데이트·복구
- 실행한 명령과 실패 단계, 재현 순서
- 기대한 동작·실제 동작, 오류 메시지
- 필요한 경우 `bash scripts/diagnose.sh` 결과 중 개인정보를 지운 부분

비밀번호, 토큰, 지갑, 거래내역, 회사 내부정보, 개인식별정보를 게시하지 않습니다. 지원은 현재 공개 버전과 표준 경로의 재현 가능한 문제를 중심으로 진행하며 응답 기한·상시 지원을 보장하지 않습니다. 매매 판단이나 회사 환경 배포는 지원 범위에 포함하지 않습니다.
